# Premium Landing Page

## Purpose

Help AI coding agents create polished, professional, responsive landing pages with strong visual hierarchy, purposeful interactions, and maintainable frontend architecture.

The objective is to translate product requirements and visual references into high-quality working interfaces.

## Workflow

### 1. Understand the product

Identify:

- Product or service.
- Target audience.
- Primary conversion goal.
- Main value proposition.
- Required sections.
- Brand identity.
- Visual references.
- Existing technology stack.

Do not invent product claims, customer testimonials, statistics, or endorsements.

### 2. Analyze visual references

When references are provided:

1. Examine layout and composition.
2. Identify typography and hierarchy.
3. Study color relationships.
4. Identify spacing and grid patterns.
5. Review imagery and visual assets.
6. Understand interactions and motion.
7. Identify responsive behavior.

Separate essential design characteristics from optional decorative effects.

### 3. Establish the design direction

Define:

- Visual concept.
- Color palette.
- Typography system.
- Spacing scale.
- Content width.
- Layout grid.
- Border and radius conventions.
- Shadow and surface treatments.
- Motion principles.

Maintain visual consistency across all sections.

### 4. Plan the information architecture

Choose sections according to actual product requirements.

Possible sections:

- Navigation.
- Hero.
- Product introduction.
- Features.
- Product showcase.
- Benefits.
- Use cases.
- Social proof.
- Pricing.
- FAQ.
- Final call to action.
- Footer.

Do not include every possible section automatically.

Every section should serve a clear communication or conversion purpose.

### 5. Implement the interface

Follow this sequence:

1. Establish global styles and design tokens.
2. Build the navigation.
3. Implement the hero section.
4. Create reusable components.
5. Implement the remaining sections.
6. Integrate images and visual assets.
7. Add purposeful animations.
8. Implement responsive layouts.
9. Validate interactions.

Follow the project's existing framework and component conventions.

### 6. Create visual polish

Pay attention to:

- Typography scale and line height.
- Consistent alignment.
- Content density.
- Whitespace.
- Image composition.
- Button hierarchy.
- Surface treatments.
- Section transitions.
- Hover and focus states.

Avoid excessive gradients, unnecessary glass effects, random decorative elements, and inconsistent spacing.

### 7. Responsive implementation

Check:

- Large desktop.
- Standard laptop.
- Tablet.
- Mobile.
- Narrow mobile screens.

Ensure navigation, text, imagery, grids, and interactions adapt appropriately.

Do not simply shrink desktop layouts to fit mobile screens.

### 8. Visual review

When browser or screenshot tools are available:

1. Run the application.
2. Inspect the rendered page.
3. Compare it with the design reference.
4. Identify layout inconsistencies.
5. Check typography and spacing.
6. Test interactive elements.
7. Correct visual defects.
8. Repeat the review.

When visual inspection is unavailable, clearly state that the rendered design has not been visually verified.

## Engineering Rules

- Use semantic HTML.
- Build reusable components.
- Keep content and presentation organized.
- Use accessible controls.
- Provide keyboard focus states.
- Optimize images and assets.
- Avoid unnecessary dependencies.
- Respect reduced-motion settings.
- Avoid layout shifts.
- Use appropriate loading and error states.
- Preserve existing application functionality.

## Expected Output

A completed landing page should have:

- Clear product messaging.
- Consistent visual identity.
- Strong information hierarchy.
- Responsive layouts.
- Reusable components.
- Functional navigation and calls to action.
- Appropriate accessibility.
- Optimized visual assets.
- Tested interactions.

## Common Mistakes

Avoid:

- Generic template-like layouts.
- Unnecessary content sections.
- Weak typography hierarchy.
- Inconsistent spacing.
- Oversized hero content.
- Decorative animation without purpose.
- Fake testimonials or statistics.
- Nonfunctional buttons.
- Poor mobile navigation.
- Unoptimized imagery.

- [ ] Design tokens established.
- [ ] Components implemented.
- [ ] Responsive layouts checked.
- [ ] Navigation and interactions tested.
